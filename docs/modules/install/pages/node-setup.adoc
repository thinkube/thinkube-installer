= Prepare your machines
:page-type: how-to

_What each machine needs before the installer can reach it, and what the installer does to it that you do not have to do yourself._

.TL;DR
Ubuntu Server 24.04, one sudo user with the same name and password on every machine, OpenSSH, and internet access. That is all you prepare; the installer does the rest over SSH.

== What each machine needs

* Ubuntu Server 24.04 LTS. The installer checks the version and refuses others.
* A user that is not root and can use sudo. Use the same username and the same password on every machine; the SSH screen of the installer relies on it.
* OpenSSH server installed and running.
* Internet access, for packages, container images and model weights.
* For the control plane: a physical machine, not a virtual one, with at least 16 CPU cores and 64 GB of memory.
* For GPU nodes: an NVIDIA driver at version 580.0 or newer. If the driver is older or missing, the installer offers to install one during hardware detection. GPUs older than the Volta generation are not supported.

Two hardware configurations have run this: a DGX Spark (GB10, arm64) and an x86-64 workstation with RTX 3090s, both on Ubuntu 24.04.

== What you do not have to do

Earlier versions asked you to grow the root filesystem by hand. Ubuntu Server's installer leaves the root logical volume at about 100 GB whatever the disk size. The installer's `15_expand_lvm.yaml` playbook now detects that case on every node and grows the volume and the filesystem to the whole volume group. Machines that are not on LVM, or already use the full disk, are left as they are.

The installer also:

* installs Tailscale on every node and joins it to your tailnet;
* installs Git, Python and Ansible where they are missing;
* configures SSH keys between the nodes;
* loads the kernel modules and sysctl settings Kubernetes needs;
* on a DGX Spark, turns swap off and sets `vm.swappiness=1` and `vm.dirty_bytes=256MB`, so a full unified-memory pool kills the offending process instead of freezing the machine.

== Docker

The installer does not use Docker and does not touch it. Kubernetes runs its own containerd. NVIDIA's DGX Spark playbooks, which use Docker, keep working beside the platform; the two share the GPU, so memory used by one is not available to the other.

== Check a machine before you start

On the machine:

[source,bash]
----
lsb_release -d          # Ubuntu 24.04.x LTS
sudo -v                 # asks for your password and returns
systemctl is-active ssh # active
nvidia-smi              # GPU nodes: driver version 580 or newer
----

== After the install

Each node is a device on your tailnet:

[source,bash]
----
tailscale status
----

== Limits

* Ubuntu Server 24.04 only; the installer refuses other versions.
* The control plane must be a physical machine with at least 16 CPU cores and 64 GB of memory.
